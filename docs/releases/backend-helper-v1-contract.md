CLI: `node deploy/stable/backend-release.mjs OP --request /absolute/private/request.json --result /absolute/private/result.json`.

Operations: `inspect`, `fence-acquire`, `fence-recheck`, `fence-release`, `backup`, `postflight`, `rollback-plan`.

Request (strict keys): `protocolVersion:1`, `operation:OP`, `transactionId` (8–80 ASCII alphanumeric/hyphen), `installationManifestPath`, `targetRecordPath`, `targetRecordSha256` (64 lowercase hex), `evidenceDirectory` (absolute private0700 directory), optional `fencePath` (required for fence-acquire/recheck/release/backup/postflight/rollback-plan), optional `backupPath` (required backup/postflight/fence-release/rollback-plan), optional `previousManifestPath` (required rollback-plan). Paths absolute. Input JSON files regular, owned by caller, no symlinks, mode0600/0400; evidence directory0700. No secrets in argv or stdout. Request and result distinct.

Result (atomic0600): `protocolVersion:1`, `operation`, `transactionId`, `disposition:"ok"|"blocked"|"maintenance_required"`, `reason` (stable uppercase machine code), `evidence` object containing only paths/hashes/counts/identities explicitly whitelisted. Exit0/2/3 respectively. CLI syntax64; unexpected error70 emits only sanitized `HELPER_FAILED`. No raw command stderr, SQL rows, environment or credential output. Receipt/backup paths appear only in private result. Consumers check BOTH exit and matching envelope/disposition; missing/interrupted result is failure.

Helper reads `backend.ownership:"managed"`, `backend.project`, `backend.revision` full40, `backend.imageId` immutable sha256 image ID, `backend.databaseVolume`, `backend.uploadsVolume`, `backend.origin`; `release:{version,webSource,backendSource}` full40 SHAs. Add `backend.helper:{schemaVersion:1,databaseContainerId:<full64>,writerContainerIds:[<full64>],databaseName, databaseUser, databaseNetwork, uploadsMount:"/app/uploads",databaseMount:"/var/lib/postgresql/data",settingsPaths:[<absolute private files>],productBaseline:"24704e11143a0bf919559a41324603f936ae03cf",migrationFingerprint:<sha256 from observed baseline Flyway tuples>,jarSha256:<actual artifact>,sourceCheckout:<absolute exact candidate checkout>}`. No passwords: use existing PG container's environment via inside-container shell; never print env. `backend.source` remains Web-owned source location; explicit sourceCheckout is helper Git parity checkout. No external/reuse ownership allowed v1.

## Required sequence

Web holds installation update exclusive lock. Stage/build before downtime. `inspect` readonly observes running exact app and DB plus live SQL match state. Web stops **all exact owned API/app writers, leaves PostgreSQL running**. No kill/stop foreign containers.

`fence-acquire` validates actual fixed DB container+volume, stopped writer IDs and their mounts/image/project, DB network is internal, has no DB published ports, and contains no unknown attached running containers. Database may have only that isolated network; reject shared/noninternal networks. Recheck actual SQL (all matches with started_at IS NOT NULL AND ended_at IS NULL) and zero other client sessions in pg_stat_activity, not a supplied receipt/boolean. Write private transaction-bound fence receipt containing manifest+record digests and exact observed container/network/volume identity. `fence-recheck` repeats observations and equality; `backup` repeats before AND after artifacts. No persistent PostgreSQL lock is claimed. Local Docker administrators are outside this cooperating updater ownership boundary; external/shared DB layouts block.

Backup operation writes new private backupPath directory (must not exist): DB custom-format pg_dump, uploads tree via stopped writer container `docker cp` to private path, settings copies, hashes and dump-list verification. Completion manifest atomic only after final quiet-point check. No DB restore command exists. Failed artifacts retained incomplete and must never be consumed as successful backup. Actual restore proof is162 synthetic rehearsal.

**Ingress:** target must run on an isolated internal backend network without a published API port during postflight. Only owned internal target writer(s) are allowed on this network; public Web ingress stays maintenance. W114 must provide an ingress/proxy or equivalent staged-container routing that can reopen without recreating the checked source/DB identity. Direct published Backend API during postflight is unsupported and fails closed. Existing direct-port installations require staged routing/adoption before an update, not a false fence claim. Probe sporting API from DB container using available image-internal HTTP utility (tool availability verified in162), not host Swagger. No host additional program required.

`postflight` verifies target exact image/source/JAR, DB identity/migration fingerprint, DB content fingerprint and uploads/settings hashes against backup, bounded sporting GET and no IN_PROGRESS. Persistent gate remains W114 ownership. `fence-release` after successful postflight writes private release receipt; Web reopens owned ingress only when result ok. Failures leave maintenance. `rollback-plan` readonly allows only previous exact pair explicitly listed in record and proven current unchanged247 product/migrations/data; unknown schema/source returns maintenance_required, never overwrites DB.

Receipt is evidence, never an authorization bearer. Every operation reobserves resources. Stable publication, shared QA and actual platform proof remain independent.

## Frozen evidence fields (consumer contract)

Every evidence object contains `schema:9`, `activeMatches:<integer>`, `current:{version,web,backend}`, `target:{version,web,backend}`, `identity:{instanceId,databaseContainerId,databaseVolume,uploadsVolume,origin}`, `compatibility:{verified:true,productBaseline:<247>,migrationFingerprint:<sha256>}` only on successful verified observation. Failure evidence is `{}` (reason is enough; private diagnostics are not printed).

- inspect adds `runtime:{imageId,jarSha256,sourceSha}`, `ready:true`.
- fence-acquire/recheck add `fencePath`, `fenceSha256`, `quiet:true`. Caller supplies `fencePath` ALSO for acquire; create must refuse existing path. Receipt pins previous manifest digest, previous observed identity, previous current pair, record hash and transaction. Recheck/backup require same original manifest digest and actual observations; postflight intentionally accepts new target manifest only when fixed identity (DB container, volumes, installation ID and origin), original pair and record digest remain identical and new pair equals record targets.
- backup adds `backupPath`, `manifestPath` (=backupPath/manifest.json), `manifestSha256`, `complete:true`. Directory supplied by caller; helper owns new creation and failure markers. Completion requires dump/uploads/settings hashes + before/after actual quiet observations. `complete` proves artifact completion, not actual restore rehearsal (162 owns actual restore proof).
- postflight adds `verified:true`, `preserved:true`, `runtime:{imageId,jarSha256,sourceSha}`, `postflightPath` (=evidenceDirectory/transactionId.postflight.json). Receipt stores target manifest digest, record/backup hashes and fixed identity. Gate remains closed. DB content fingerprint, uploads tree and settings hashes equal backup; no destructive restore.
- fence-release adds `released:true`, `releasePath` (=evidenceDirectory/transactionId.released.json); requires successful postflight receipt bound to current target manifest and reobserves target identity/gate. It does not open ingress itself.
- rollback-plan adds `compatible:true`, `previous:{version,web,backend}` from previousManifestPath. Allows app-only previous source when exact tuple is in supportedSourcePairs, all source product/migration parity and current observed DB prove247/V9 unchanged; no automatic DB operation. Unknown returns maintenance_required/ROLLBACK_UNPROVEN and `{}`.

Ingress frozen with W114: API/DB internal backend network only, no published ports; exact owned nginx has backend+edge networks and sole saved API published origin. Manifest `backend.ingress:{configPath,containerId,imageId,backendNetwork,edgeNetwork}`; helper also sees ingress via this field (no duplicate helper.ingress IDs). Private config hash and live GET503 + `X-UltiStats-Instance:<instanceId>` + actual exact Docker image/container/mount/project prove gate; all other backend network clients must be exact old/target writer IDs. No external/loopback API shortcut. `inspect` permits open recognized ingress; quiet/target operations require closed gate.

Compatible app rollback: `rollback-plan` additionally returns `rollbackPlanPath` (evidenceDirectory/transactionId.rollback-plan.json). Optional request `rollbackPlanPath` accepted ONLY by postflight/fence-release: verify bound planner receipt (transaction, original record/backup/fixed identity, exact supported previous pair), then accept previous pair instead of record target. Actual unchanged DB content/migrations/uploads/settings and previous source/JAR/image are reobserved; target being stopped is acceptable while planning. No DB restore. Postflight receipt and release result distinguish actual current previous pair truthfully.

Bootstrap `inspect` alone permits null expected migrationFingerprint/jarSha256 and returns observed verified values at compatibility.migrationFingerprint/runtime.jarSha256. Export `observeRuntimeIdentity({installation})` from `deploy/stable/observe.mjs` observes the same values after ownership/source/migration validation. Backup/postflight never accept null. This is observation of fresh managed setup, not ownership adoption by guessing.

Rollback-plan also requires fencePath+backupPath; no completed verified backup/quietpoint means maintenance. Rollback mode receipt names are `<transactionId>.rollback-postflight.json` and `.rollback-released.json`, distinct from failed target proof. Normal receipt paths remain `.postflight.json`/`.released.json`. Planner uses preserved original source/image identity already verified by the fence, verifies retained previous source/image again, then restored previous runtime is checked in rollback postflight using its newly observed container IDs.

Readonly observer supports stable and dev isolated namespaces for startup; updater CLI remains stable-only. Inspect accepts either an explicitly supported previous pair OR the already installed exact target (for no-op), still requiring all actual runtime/schema/source proofs. It does not permit fencing an unlisted source pair.

Rollback postflight/release independently requires planner.previous equal the original backup fence.current and the record's explicit supportedSourcePairs; a claimed compatible flag cannot substitute a pair. The restored previous runtime must use the original fenced immutable image/JAR/source identity. Private backup uploads are a copied tree with path/content hashes (not a host-tar dependency).

## Source bytes and capacity extension (v1 optional evidence)

`sourceProof:{sourceSha,trackedFileCount,byteIdentical,eolDelta:[{path,rawSha256,actualSha256,reason}]}` is returned by the readonly observer and common successful helper evidence. All tracked regular files and index entries independently match raw Git objects through `hash-object --no-filters`; hooks, filters, replace refs and optional index writes are disabled for observation. Unknown/untracked paths, symlinks, staged changes and byte changes fail. A stat-only Git status/EOL discrepancy cannot substitute raw byte/index verification.

Root's narrow readonly legacy exception applies only exact source247 `gradlew.bat`, blob db3a6ac207e507b0bc1635a9f2c18d3b174e682e: either canonical LF SHA25694102713eb8fb22d032397924c0f38ab2da783ba60d07054339f1190a0c4e2cd, or byte-for-byte tracked-attribute LF→CRLF. The latter reports byteIdentical:false, reason tracked-attribute-CRLF and both actual/raw hashes. Mixed EOL, encoding changes, other paths/SHAs or symlinks are rejected. All new candidate source materialization/build stays raw strict; no old-checkout helper/batch file is executed. Optional installation.tooling metadata belongs Web and separates verified new controller source from actual old application identities; it never changes backend.helper.sourceCheckout or aliases its SHA.

`capacity:{verified:true,backupDirectory,databaseBytes,uploadsArchiveBytes,settingsBytes,requiredBytes,availableBytes,temporaryRequiredBytes,temporaryAvailableBytes}` is required on successful CLI inspect/backup. All byte counts are nonnegative decimal STRINGS; databaseBytes and requiredBytes positive. Caller may supply the existing optional backupPath on inspect to bind the exact future backup directory (otherwise evidenceDirectory/backup). Node statfs checks its private parent and temporary filesystem, actual pg_database_size, bounded in-memory Docker uploads TAR byte count and private settings sizes. Base destination budget is2*DB+2*uploadsArchive+settings+64MiB, temporary budget2*uploadsArchive+128MiB; same-filesystem budget includes both. This is conservative preflight evidence, not a reservation or a promise that another host process cannot consume space. Backup repeats immediately before creating artifacts. Unknown/insufficient capacity fails closed; no host du/tar/Python/jq/psql program is needed. TAR stream and custom dump are individually bounded at256MiB; larger inputs require a reviewed streaming extension.

Normal startup `observeRuntimeIdentity` verifies known ongoing-match state without blocking it; restarting the installed version is separate from updating. CLI inspect and all update/fence/backup/postflight paths still require zero IN_PROGRESS. The readonly startup observer never authorizes switching or backup.

Canonical version boundary: authoritative record.version is plain SemVer (`0.1.0`); every installed/staged/result current/target/previous pair.version is `v<semver>` (`v0.1.0`) or exact `unpublished` for the actual original39/247 installation. Only record→target conversion adds the prefix. No loose stripping or normalization of unknown version strings; rollback retains the exact previous manifest version.
