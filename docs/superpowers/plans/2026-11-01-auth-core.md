## Global constraints

- Only additive V11; V1–V10 immutable. Installation UUID generated once in DB.
- Password 8–1024 Unicode code points, reject unpaired surrogates, retain spaces.
- 14*24h inactivity; only explicit renew advances lastActivityAt, monotonic server
  time; GET/poll/SSE/ordinary writes/password/reauth do not advance activity.
- Step-up 300 seconds. Temporary-password accounts have no protected permissions.
- All three captured UUID headers before protected effects; private reads validate
  complete identity whenever any header is supplied; login installation only.
- No HTTP bootstrap/default secret, secret argv/log/export or bearer JSON/storage.
- CD151 source gate before merge; no human runtime, trust, DNS or rollout changes.
- Source/ports API21152 PG22152 are owned only after checking availability; JVM
  and Docker/browser locks follow standing worker instructions.

## Review focus

1. Stale cookie/logout after account switch cannot revoke or clear newer session.
2. Role/block/reset versus concurrent writes cannot use stale authorization.
3. Concurrent last-admin changes/recovery preserve an active administrator.
4. True expiry boundary cannot renew/revive; passive traffic never changes activity.
5. Masked JSON CSRF roundtrip and refresh after credential changes work on real HTTP.

```kotlin
// package com.github.mihanizzm.ultistats.auth.model
enum class AuthEntryMode { ANONYMOUS, SECURE, LOOPBACK }
enum class AuthPermission { SPORTS_WRITE, STATISTICS_READ_ALL, TRANSFER, OBS_ADMIN, API_DOCS, ACCOUNT_ADMIN }
data class AuthPrincipal(val installationId: UUID, val accountId: UUID, val sessionId: UUID,
    val permissions: Set<AuthPermission>, val passwordChangeRequired: Boolean)
// package com.github.mihanizzm.ultistats.auth.security
interface AuthEntryClassifier { fun classify(request: HttpServletRequest): AuthEntryMode }
interface AuthRequestAccess {
    fun requirePermission(request: HttpServletRequest, permission: AuthPermission): AuthPrincipal
    fun validateExpectedIdentity(request: HttpServletRequest, principal: AuthPrincipal)
}
```

Request attribute `AuthPrincipal::class.java.name` holds current principal. Security
Authentication principal also contains this type. `AuthService.installationId():UUID`
is shared with154. `AuthProblem(status:Int, code:String)` is rendered as RFC9457
with requestRejectedBeforeExecution for pre-controller rejection. #153 may throw
this problem. No consumer reads secret session/account repository records.

Service signatures (DTOs follow exact frozen contract):
`context(credential:String?):AuthContext`, `login(login:String,password:String,
previousCredential:String?):AuthLoginResult`, `renew(principal:AuthPrincipal):AuthContext`,
`logout(credential:String,expectedSessionId:UUID):LogoutResult`,
`changePassword(principal:AuthPrincipal,currentPassword:String,newPassword:String):AuthContext`,
`reauthenticate(principal:AuthPrincipal,password:String):Instant`,
`listAccounts(page:Int,size:Int,search:String?):PageResponse<AccountView>`,
`createAccount(actor:AuthPrincipal,request:CreateAccountRequest):TemporaryAccountResult`,
`updateAccount(actor:AuthPrincipal,id:UUID,request:UpdateAccountRequest):AccountView`,
`resetPassword(actor:AuthPrincipal,id:UUID):TemporaryAccountResult`.
