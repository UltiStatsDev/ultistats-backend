## Global constraints

- Only additive V11; V1–V10 immutable. Installation UUID generated once in DB.
- Password 8–1024 Unicode code points, reject unpaired surrogates, retain spaces.
- 14*24h inactivity; only explicit renew advances lastActivityAt, monotonic server
  time; GET/poll/SSE/ordinary writes/password/reauth do not advance activity.
- Step-up 300 seconds. Temporary-password accounts have no protected permissions.
- All three captured UUID headers before protected effects; private reads validate
  complete identity whenever any header is supplied; login installation only.
- No HTTP bootstrap/default secret, secret argv/log/export or bearer JSON/storage.
- CD151 source gate before merge; no human runtime, trust, DNS or rollout changes.
- Source/ports API21152 PG22152 are owned only after checking availability; JVM
  and Docker/browser locks follow standing worker instructions.

## Review focus

1. Stale cookie/logout after account switch cannot revoke or clear newer session.
2. Role/block/reset versus concurrent writes cannot use stale authorization.
3. Concurrent last-admin changes/recovery preserve an active administrator.
4. True expiry boundary cannot renew/revive; passive traffic never changes activity.
5. Masked JSON CSRF roundtrip and refresh after credential changes work on real HTTP.

`AuthDomainTransactionAdvisor` uses actual Spring TransactionAttributeSource,
including jakarta annotations, with transaction advice order0 OUTER and authority
advice order1 INNER. Only captured protected unsafe DOMAIN requests enter it.
Inside the ORIGINAL non-readonly domain service transaction it asserts actual
transaction, threadbound SAME physical JDBC/JPA connection and autocommit=false,
READ_COMMITTED isolation; acquires pg_advisory_xact_lock_shared(1598115923,152)

Original service commit/rollback remains outside advisor, before controller body;
no outer HTTP transaction, extra connection, or propagation changes. Connection
loss releases lock AND rolls back the same mutation transaction atomically.

AuthStore.withAuthorityLock opens its own management TransactionTemplate, acquires
pg_advisory_xact_lock EXCLUSIVE on SAME connection/key first, THEN singleton row
FOR UPDATE. OwnerCLI follows identical order. Hash/verification outside management
transaction, hash/current-authority recheck inside. No SHARED→EXCLUSIVE upgrades;
core management routes never enter domain advisor. Non-readonly nested domain
methods reuse original transaction fence; GET/SSE/readOnly calls hold no fence.
