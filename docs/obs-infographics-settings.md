# Интервалы инфографики OBS

На `/obs-admin.html` три независимых поля: «Ростер команд», «Состав на поинт», «Лидеры матча». Каждое принимает целое число от 2 до 15 секунд, по умолчанию 5. Сохранение и перезагрузка сохраняют все три значения. Настройки Event Log, его TTL/maxRows и профили табло независимы.

`GET /api/v1/obs/infographics/settings` возвращает `{rosterPageSeconds, pointPageSeconds, leaderPageSeconds, revision}`. `PUT` требует все три поля как настоящие JSON integer: дроби, строки, boolean, null и отсутствующие поля дают 400. API требует HTTPS, OBS_ADMIN, штатную captured staff session; PUT также требует CSRF. Ответы no-store. Вход через прежний Web staff-auth-v1; viewer key не даёт права на настройки.

`revision` — durable Long, увеличивается только при изменении значений. PUT тех же трёх значений возвращает прежнюю ревизию, не добавляет историю и не перезапускает показ. Последнее сохранение побеждает; изменения сериализуются на singleton-строке. Старый PUT `/api/v1/obs/config` не меняет интервалы.

Снимок различает текущие `settings` и действующий `phase.pageSeconds`. Ростер захватывает интервал на `effectiveStartedAt`, состав — на стабильное `lineupStartedAt`. История настроек обеспечивает тот же интервал после reload/reconnect; фазы до первой записи сохраняют реальный прежний default5. Минимальный полный проход ростера использует захваченный интервал ростера. Будущий переход из ROSTER в LINEUP получает отдельный `phase.lineupPageSeconds`, поэтому локальное переключение не использует интервал ростера. Пока будущая фаза ещё не началась, очередное сохранение может изменить её интервал; уже начавшуюся фазу не перематывает.

`settings.revision` входит в `presentationRevision` даже при неизменном интервале текущей фазы. Следующий consumer команд лидеров должен привязать admission/expiry к этой ревизии и захватить `leaderPageSeconds` при новом показе; изменение ревизии делает предыдущую команду неэффективной. Этот leaf не вводит команды show/hide.

V23 создаёт отдельные singleton и историю; чтение не создаёт строк. Старые source keys/HMAC и игровой журнал не изменяются. История сохраняется для стабильного вычисления старых эпох; автоматическая очистка не вводится.
